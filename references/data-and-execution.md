# 数据与执行映射

## 输入及取数

脚本仅需Python标准库，取数使用Node与已安装的`ifind-finance-data/call-node.js`。不要把iFinD密钥、账户号码、真实持仓截图或完整历史数据装入技能。

先核实代码与产品，再选择stock/fund服务；基金代码不能替代T+0/T+1产品核验。常见标准主板/创业板A股买入100股整数倍；ETF通常100份，但特殊产品仍以官方规则为准。当前未覆盖科创板最低200股及其他特殊交易单位。

行情每月分批，避免iFinD返回截断。曾出现“最低价”被解析成区间最低价，必须检查原始表头和指标语义；缺少每日最低价就重新查询，不能填充区间最低价。只保留目标证券标识，不把`.OF`净值或别名混入`.SH/.SZ`场内价。

- 同日重复OHLC不一致、乱序、未来日期、非正价格、最高/最低逻辑错误必须失败。
- 来源返回节假日占位但OHLC为空，记录后过滤；工作日缺失须核实停牌/休市，不能假装全年无缺口。可与同市场已验证的流动标的交易日历交叉核对。
- 保留原始响应、请求范围、抓取时间、symbol、复权口径、缺失/过滤/重试记录及数据SHA256。
- 报告截止日在盘中时，不把尚未结束的日K线当成完整观察值。快照与历史数据分开保存。
- iFinD当前高频工具仅支持当日日内查询；没有真实历史分钟数据就明确日线情景模拟。

## 公司行动文件

运行前创建JSON，例如：

```json
{
  "verified": true,
  "checked_through": "2026-10-13",
  "source_urls": ["实际核验的官方公告URL"],
  "events": [],
  "other_actions": []
}
```

发生现金分红时：`events`填`{"date":"YYYYMMDD","cash_per_share":税前每股现金额}`，date为除息日，不是公告日。核实权益登记/除息关系。只有完成证据核验后才能写`verified:true`；日期覆盖数据末日。脚本不把布尔值当外部真实性证明，调用agent负责证据来源。

A股现金分红用保守20%税后应收进入总权益，到账日未知时不作为期间可用资金，连续模式保留应收，不因统计窗口或数据截止日假装到账；这不是精确按持有期追缴的税务模型。ETF分红按产品适用税收说明核对。转增/送股/拆分不在当前模型内，不能直接喂未复权价格；有事件先报告不支持，不能偷偷换前复权价凑结果。

## 交易模型与费用

A股支持T+1：当日卖出受隔夜可卖库存限制，不是“全天不能做任何买卖”。有旧仓可以先买后卖旧仓，但不能无限循环卖掉当天新仓。止损先卖旧仓，新仓等下一可成交交易日，连续模式末日照常交易；一字价/停牌日不假定能成交，期末持仓按市值计权益并标出未实现部分。

ETF应核实结算方式，不按“所有ETF均T+0”处理。报价单位ETF0.001元、股票0.01元。默认佣金来自本用户已确认的研究假设；新费率覆盖它。股票卖出印花税万五、双边过户费十万一是编写时基线，应核实研究区间及当前适用规则；不要把净佣/全佣混淆后重复计规费。

公开核验入口（重新读取适用规则，不把链接存在当实时确认）：
- 深交所交易规则：https://www.szse.cn/lawrules/index.html
- 上交所ETF问答：https://www.sse.com.cn/assortment/fund/etf/question/
- 2023证券印花税减半公告：https://shanghai.chinatax.gov.cn/zcfw/zcfgk/yhs/202308/t468451.html

## 震荡阶段与统计窗口

一年行情是背景，不是固定回测区间。先辨别趋势下跌/上涨、反弹及价格反复往返阶段；记录中枢是否移动，不把“跌了很多”当横盘。送转和现金除息不能制造假低位或假穿越；原始价格供撮合，已核验现金分红可加回仅用于价格频率诊断。送转仍需另行建模。

由调用agent根据价格证据生成阶段文件；无需用户反复批准合理的研究假设，但要说明不确定性。示例格式（日期与理由必须来自本次分析，不能原样套用）：

```json
{
  "start": "2026-07-01",
  "status": "candidate",
  "selection_mode": "retrospective",
  "evidence_as_of": "2026-10-13",
  "reason": "此前持续下行，随后多次在相近价格带往返；区间中枢是否稳定仍需复核"
}
```

`status`可以为`candidate`、`uncertain`、`not_sideways`；后两者不优化。`selection_mode`只允许`retrospective`或`user_supplied`，不支持宣称已实现因果/实时横盘检测。起点必须是实际观察到的交易日，证据不能来自研究截止日之后，理由不能是某日回测更赚钱。候选阶段未被脚本证明为横盘；`selection_verified:false`必须保留。

`regime_windows.py`采用透明、可检查的回看启发式：
- 用阶段收盘价中位数作描述性中枢；半个绝对日变动中位数作死区，过滤小幅来回穿越；现金分红按除息日累计每股税前额加回，仅供诊断。
- 价格跨死区两侧后回到原侧记一个完整往返，不把日内最高最低顺序臆造为已知轨迹。
- 至少观察到两个完整往返时，统计长度取约两次典型往返所需观察值，最多为阶段长度；否则整段只作一个统计段。公式和往返数写入报告，**不是已验证的最优窗口算法**。
- 从阶段起点向后分完整等长窗，尾段保留且单列，不丢弃起点或尾部来凑四轮。允许`--window-days`显式覆盖统计长度，但没有15或60的默认值；覆盖不能绕过不足两个完整价格往返的证据门槛。

如果当前阶段开始早于已取得背景数据，说明左侧截断并补证；不能把数据文件的第一天冒充真实震荡起点。很短、单向或证据不清的阶段，不强行搜索出一个最佳网格。

## 候选搜索与覆盖

由`run_study.py`生成和评估候选，不另写收益榜或手选几档代替搜索。每个维度独立决定自动/显式：省略`--lots`或`--grids`才自动搜索该维度；显式列表不追加邻居、不改范围。初始/底仓/上限比例保持输入值，不随候选优化，也不擅加单笔资金比例限制。

- **数量范围。** 按历史阶段启动价、预算及初始/底仓/上限比例换算100单位整数倍份额，使用含入场费用后可承担的模拟初仓。`--holdings`只用于当前配置核对，不替换历史初仓或改变历史搜索上限；若要接续实际持仓，需单独明确回放状态，不能把当前股数移植到历史。初始可买空间为`cap - initial`，可卖空间为`initial - floor`，取两者最大值作为数量上限，从100起按100递增。这个上限允许一侧空间较大的候选接受模拟检验，不表示该候选一定可双向成交；模拟撮合仍受该策略预算现金、费用、库存与T+1限制；多策略共用账户现金需额外核对。
- **数量粗细搜索。** 不超过96个数量档位时全搜；超过时粗采样覆盖上下端点与仓位转换点，再围绕粗排前3名按100单位做局部细搜。具体细搜半径和已评估候选记录在结果中；漏搜的范围必须标为部分覆盖，不把粗采样称为全搜。
- **间距粗细搜索。** 股票默认粗档为0.5、0.8、1、1.2、1.5、2、2.5、3、4、5%，ETF为0.4、0.5、0.6、0.8、1、1.2、1.5%；在粗排前3名的相邻粗档区间内按0.1个百分点细搜，不超原粗档最小/最大值。这里是百分点，例如1.0%相邻为0.9%/1.1%，不是乘以1.001。
- **邻域核验。** 细搜后对第一名检查数量±100、间距±0.1个百分点的合法邻居，仅扩展自动维度且不超搜索范围，最多迭代4轮；报告最终胜者的合法邻居及各项是否已计算；`evaluated:false`即未覆盖项，迭代期间若出现更优候选会重新选择胜者。达到迭代上限仍未覆盖最终胜者邻域时必须披露。若胜者仍在范围边界或检查后不能确认局部优势，明确局部最优尚未证实。邻域检查不能证明全域最优。

粗排、细排与最终比较都沿用完整窗口均值/方差Pareto口径，不能改成按总PnL排名。阶段不适合优化、完整价格往返不足或完整统计窗不足时，排名保持为空；只报告诊断和已计算情景，不绕过门槛另称“收益最优”。

搜索元数据至少解释自动/显式维度、理论范围与实际评估范围、候选数量、`coverage`、粗细搜索和邻域结果、上下边界命中情况。数量全覆盖也不代表数量×间距的全部组合全覆盖；必须按实际组合说明。报告同时给每笔参考金额（数量×参考价）、占总预算比例、初始向上可卖档数与向下可买档数；档数按对应库存空间除以每笔数量取整，只表示仓位空间，不承诺现金或行情足够成交。历史评估用历史启动价；给当前配置时另附当前参考价日期，不能混用。

1500股低价股票可能仅约5000元，不能仅按股数称“大单”。用户已有真实策略时，将原数量、间距、仓位及基准单独作为原方案对照；不能为了展示自动候选更好而重置其基准或改变持仓比例。同一策略内各档使用同一现金池，不为每档重复分配预算。

## 连续运行与统计解释

主入口对每组参数调用一次连续引擎：阶段首日收盘建仓，之后持仓、现金、基准和T+1可卖库存持续承接；末日按市值记账，不默认强制平仓。`grid_engine.run`保留`liquidate_end=True`用于旧脚本兼容，主入口明确使用`False`。这不影响本金止损：止损仍可全清旧仓，锁定新仓等下一可成交日，随后本段不重启。

完整窗口的盈亏是同一条净值曲线端点之差，首窗从初始预算开始；全部完整窗及尾段相加严格等于整段总盈亏。统计切分不触发订单，不产生额外入场/离场费用，改变统计窗不能改变某组参数的交易序列与总盈亏。

等长完整窗至少两个才计算样本方差（n-1），否则方差/标准差为null并报告不足。尾段不混入跨窗方差，但计入总盈亏。还需报告每日净值波动、最差完整窗和最大回撤；窗口共享一条策略状态，不是独立重复试验。不能直接把不同长度窗口的方差当成相同风险量度比较。

用窗口均值/方差Pareto及较低均值/较高标准差辅助比较，同时核对整段含尾部的总盈亏；不能用前面窗口盈利掩盖尾部巨亏。初仓、底仓、上限比例是固定研究条件，不称为优化结果。持有不动、相同本金止损和现金使用同一阶段与初始预算对照。

固定主候选后，改变相邻统计窗只重新统计同一条净值；起点前后移动是另一入场情景，单独标示，不把它们合成独立样本或用来回头挑最漂亮起点。单个阶段的样本内结果不能证明未来横盘会持续；已震荡时间不等于未来可运行时间。

## 从结果到APP

只在用户要配置时按其真实界面映射。重要对应：

| 模型 | 页面对应与限制 |
|---|---|
| 初始价 | 新策略启动参考价；附时间，不把成本价自动填作基准 |
| 基准更新 | 模型按成交价更新；“到价触发就更新”是另一机制 |
| 间距 | 输入框已有%时填0.5代表0.5%，不是0.005 |
| 手数 | 股/份数量，不是资金金额；禁止无说明加倍 |
| 仓位范围 | 指总持仓，不是可用数量，也不是“大约可买” |
| 买入/卖出报价 | 限价：买用卖一、卖用买一；仍可能不成交 |
| 有效期 | 区分自然日/交易日；软件最长20/60自然日不等于研究周期 |
| 自动运行 | “自动下单”不证明云端托管；退出APP/断网的行为查当前官方说明 |
| 策略停止 | 最大持仓、价格区间均不等于本金止损；停止网格也不等于平仓 |

同花顺专业终端文档不能套到手机APP。原生券商APP是否支持仓位上下限/云端/联动退出，要逐项读说明或截图；截图未显示的字段不能声称已设置。

用户要求无人值守时，不建议靠逐笔手动确认维持原模型。平台不能实现必要控制时，输出具体缺口并查兼容的原生执行入口；不擅自删除风控或宣称可直接运行。严格交替买卖是不同策略，需另算，不能沿用原收益。

新建/迁移同一标的网格前核对旧单状态，避免两个客户端重复运行。A股从空仓建底仓后需可卖库存才能完整启动双向网格；ETF根据已核实结算规则执行。技能本身不提交任何金融订单。
